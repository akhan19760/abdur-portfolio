# How the stages use the taste skill

The orchestrator (the main session) follows this. It is kept by every purge.

1. **Finalists board.** The scout shows all five references, ranked, with its
   recommended two marked. Taste is not involved yet. Build and record the board with
   the `board` skill.
2. **Owner chooses any two sites.** There is no lead and no support. Record both in
   DIRECTION.md. The owner then picks per category, from either site (the font from
   one, the footer from another, and so on).
3. **Taste prepares the board.** Load `design-taste-frontend`. Do its steps 1 to 4 for
   this portfolio:
   - Inventory what belongs only to this owner, from `workflow/content.md`.
   - Write the argument: one claim per section. The section list goes on the board.
   - For every category (type, palette, hero, each section, footer, motion, scenes),
     list the option each of the two sites offers, measured from the scout's briefs
     and screenshots, each with the twist it would need.
   - Hold every option against taste's house rules and laws. Mark which options pass,
     which need a rule waived (and why), and which one taste recommends and its
     reason. Taste advises on the board; it does not remove the owner's options.
4. **Direction board.** Show the owner every category as a row with a preview of each
   site's option, using the `board` skill. The owner picks per row, from either site.
   Record each answer in DIRECTION.md under "Board answers", with the site it came
   from and the twist.
5. **Design system, then sections.** Workers follow taste's run (see their files),
   one section at a time, each ending in the review gate.
6. **Whole-page check.** qa runs taste's inspector and critique across the page.

Any waived taste rule is recorded in DIRECTION.md with its reason.
Nothing here uses Impeccable or any other design skill.
